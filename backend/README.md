# Backend

The application requires Supabase Postgres, private Supabase Storage and Mistral. There is no runtime demo mode, SQLite database, local PDF storage or deterministic assessment fallback. Importing application modules does not connect to a database or create data. API startup and the worker entrypoint validate configuration and verify the existing database schema; neither creates tables or seeds templates.

From this directory, install with `uv sync --python 3.11`. Put these keys in the repository-root `.env`, then start both processes from the root with `backend/.venv/bin/python scripts/start_backend.py`. The launcher loads the file; explicit process environment values take precedence. Direct API/worker commands still require these values in their environment:

- `DATABASE_URL`: Supabase Postgres connection URL. `postgres://`, `postgresql://` and `postgresql+psycopg://` are accepted; SQLite URLs are rejected.
- `SUPABASE_URL`: Supabase HTTPS endpoint. Local Supabase HTTP endpoints are also accepted.
- `SUPABASE_SERVICE_ROLE_KEY`: backend-only Storage access key.
- `MISTRAL_API_KEY`: backend-only embedding and assessment credential.

Unset the obsolete `APP_MODE` variable. Supplied values are rejected. Missing configuration errors list variable names without credential values. Optional settings: `SUPABASE_STORAGE_BUCKET` defaults to `original-pdfs`, `MISTRAL_MODEL` defaults to `mistral-small-latest`, `SEARCH_ROUND_LIMIT` defaults to 3, and `FRONTEND_ORIGINS` allows localhost and 127.0.0.1 on port 3000. `SUPABASE_ANON_KEY` optionally enables public progress counters; server credentials are never returned by `/runtime-config`.

The selected MiddleGap project has both checked-in migrations applied. For another fresh project, apply `migrations/001_initial.sql` followed by `002_progress_permissions_and_indexes.sql`; do not rerun them on the provisioned project. See [service setup](../docs/setup.md) for verified permissions and the Git-ignored credential file. The original PDFs bucket must remain private, as described in [Supabase Storage access control](https://supabase.com/docs/guides/storage/security/access-control). Use a URL from your project's [database connection settings](https://supabase.com/docs/guides/database/connecting-to-postgres).

Load a real, explicitly supplied template with `uv run python -m app.load_template /absolute/path/checklist.json`. The JSON follows `../docs/api-contract.md`: ID, name, description and full domain/control/sub-control/criterion hierarchy. Validation enforces unique stable identifiers, unique positive criterion numbers within each sub-control, finite non-negative weights and configured evidence/population rules. The loader inserts a new template ID and refuses to overwrite existing data. It does not fabricate workbook rows or infer workbook rules. Existing checklist snapshots remain immutable. The UI Excel importer replaces JSON as the normal template-loading flow; actual-source mapping and scoring cases pass, while native Excel recalculation remains unverified.

Start the API with `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000` and a separate worker with `uv run python -m app.worker`. `--once` processes one queued job. One worker with sequential provider calls is supported. Expired leases permit recovery after 20 minutes. Failed criteria retry against the same snapshot and frozen population; binding-dependent conclusions remain pending until the joint document assessment succeeds.

PDFs enter the data room only through multipart `POST /workspaces/{id}/documents` with field `file`. Document connector/import/fetch/status routes are deferred and unavailable in the running application. Historical source metadata remains stored; removal of runtime connector routes does not rewrite existing document records.

Run `uv run pytest`. Tests explicitly inject an isolated SQLAlchemy database and synthetic AI/storage/index/progress adapters; no production setting enables those adapters. The separate test-only harness runs with `uv run python -m tests.integration_server seed --root /tmp/middlegap-integration`, then the same command with `api` or `worker --once`. Its API binds only 127.0.0.1 and adds `test_harness: true` to `/health`. Production `/health` returns only `{status: "ok", ai_provider: "mistral"}`. This harness verifies workflow behavior, not live provider connectivity.

Ruff configuration remains in `pyproject.toml`. Its acquisition was denied earlier, so Ruff checks remain unexecuted. An already-installed Ruff can run `ruff format --check .` and `ruff check .`; compilation and passing tests do not establish lint verification. Live Supabase schema and permissions are verified; API/worker Storage/Postgres access and Mistral calls remain pending runtime credentials.

The workbook can also be imported directly through the application. `POST /checklist-templates/workbook/preview` accepts multipart `file` and returns the source hash, counts, warnings and stable sub-control identifiers. Confirm through `POST /checklist-templates/workbook` with the same file, template `name`, `preview_hash`, explicit `default_evidence_binding`, explicit `default_population_rule` and `confirm_warnings=true`. Optional `subcontrol_rules` is a JSON object keyed by sub-control ID, containing binding/population overrides or a reviewer-supplied `expected_evidence` description. Unknown IDs or fields fail validation. Changing the file requires a new preview.

The supported Criteria Engine sheet has headers on row 11 and 188 criterion rows from 12 through 199. It maps 24 forward-filled controls and 80 sub-controls with stable hierarchical IDs. Domain headings are derived from column A and control IDs, independently of the Q/R domain summary. Column W legal references remain display-only; semicolon-separated column Z values are retrieval hints. Empty evidence expectations and applicability conditions remain empty. Lookup formulas referencing the workbook's broken `RefLookup` are retained as provenance rather than evaluated or replaced by invented guidance.

Imported templates use the `criteria_engine_v1` scoring policy only after the J/K/L/M and domain/total formula structures pass validation. It sums fixed sub-control weights for controls, averages eligible controls within each domain using the first sub-control status filter, and averages all ten domain scores for the overall score. No weights are renormalized after N/A decisions. Missing decisions remain provisional. Existing JSON templates retain their configured sum aggregation unless a scoring policy is explicitly provided. Formula text is never executed; XLSX parsing bounds compressed size, expanded size, member count and individual member size, rejects XML entities/macros, and never follows external links.

Run local actual-workbook checks with `WORKBOOK_TEST_PATH=/absolute/path/workbook.xlsx uv run pytest`. The workbook is read only and is not copied into the repository. CI uses synthetic workbook structures and skips tests that require this private source file.

Database connections are bounded per process: `DB_POOL_SIZE` defaults to 2 (allowed 1–5), overflow is disabled, and `DB_POOL_TIMEOUT` defaults to 5 seconds (finite, greater than zero, at most 30). Driver connections time out after 10 seconds and identify themselves as `middlegap`. One API process plus one worker therefore uses at most four database connections with defaults; additional processes multiply that budget. Startup closes failed candidate pools, successful reconfiguration disposes the previous pool, and API shutdown or worker entrypoint exit disposes its pool. Disposal closes returned/idle connections; request contexts must finish and return their checked-out connections normally.

Pool checkout timeout or database connection failure returns a sanitized HTTP 503 with `Retry-After: 5`. Constraint and SQL programming failures retain HTTP 500 rather than being mislabeled as temporary capacity failures. Responses never expose driver messages, SQL or connection URLs. No automatic write retry is performed: a connection failure can leave a write outcome uncertain, so verify its result before resubmitting. Startup distinguishes session-pool exhaustion from connection failure and missing schema without printing credentials.

After applying this fix, restart existing API and worker processes so they release their old SQLAlchemy pools and use the bounded configuration. The fix does not terminate other database sessions, rewrite the pooler URL/port, or change Supabase's connection limit. Live recovery must be verified after those old processes have stopped; passing simulated backpressure tests alone does not establish that the shared pooler is free.

Joint same-document groups use a session context for the whole transaction. Exceptions during result writes, progress updates or commit roll back and return their connection before the worker's failure-recovery transaction opens another session. The single-connection regression tests inject both progress and commit failures and verify rollback, released capacity and persisted recovery status.
